# ПАМЯТКА — Вероника (админ GitLab)

> Сначала `РУКАМИ.md` (что делать руками), затем PR по этой памятке.

## Один раз настроить git
`git clone <ссылка на репо, которую даст Вероника> && cd <папка>`, затем `git config user.name "<имя>"` и `git config user.email "<почта GitHub>"`. Коммиты только из своего аккаунта.

## Твои PR (по одному на issue; Вероника заводит issues, номер подставь в `Closes #N`)
### V-A — Роли и защита веток GitLab (ревьюер: Настя)
1. `git switch main && git pull && git switch -c gitlab/roles-and-protection`
2. Скопируй содержимое `V-A/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности.
3. Сделай то, что описано в `V-A/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: gitlab-protected-branches.png (настоящий скрин настроек защиты веток) — ОБЯЗАТЕЛЬНО.
4. `git add -A && git commit -m "#N: роли и защита веток gitlab" && git push -u origin gitlab/roles-and-protection`
5. На GitHub: Compare & pull request, вставь `V-A/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

## Твои ревью (чужие PR)
- `review/E-A.md` — PR E-A (Есен, ветка `infra/compose-stand`)
- `review/E-C.md` — PR E-C (Есен, ветка `docs/architecture`)
- `review/N1-B.md` — PR N1-B (Настя, ветка `onec/dev-guide`)
Как делать: открой PR → вкладка Files changed → выполни проверки из файла → поправь готовый комментарий под то, что реально увидел(а) → Approve или Request changes. Выдумывать замечания и результаты нельзя.
