# РУКАМИ — Вероника: репо, доска, затем GitLab
Есен пока без доступа к VPS, поэтому **репо и доска — на тебе**. Стенд и GitLab — когда будет сервер.

## Часть 1. Репо и доска (делай сейчас, сервер не нужен)
1. GitHub: создай новый **пустой публичный** репо (например `onec-ci-platform`) и клонируй.
2. Скопируй **содержимое** папки `BASE/` (она лежит рядом с этим файлом) в клон, не саму папку. `git add -A && git commit -m "Базовый каркас платформы" && git push`.
3. Добавь Есена, Настю, Надю и Соню как collaborators (Settings → Collaborators).
4. Включи защиту `main` (Settings → Rules → Rulesets: PR, 1 approval, без force push). **После** шага 2.
5. Создай публичный GitHub Project (доска) и 15 issues: названия и ответственные — в таблице `handout/README.md`. Колонки: Todo / In progress / Review / Done. Поставь сроки.
6. Напиши в чат ссылку на репо и на доску. С этого момента Настя, Надя и Соня идут по своим `ПАМЯТКА.md`.
7. Отправь документы куратору и схему СППР заказчику (требования 13 и 14), сохрани скрин ответа. Файлы — из `prod/docs/`.

## Часть 2. GitLab (когда есть стенд: VPS или временно локальный)
Если VPS не будет до **25.11**: подними стенд локально на ноутбуке (Docker, 16 ГБ RAM) из файлов `handout/Есен/E-A/files/docker/` и `ci/scripts/` из `BASE/`. Скрины с него подписывай «локальный стенд». Файлы Есена **не коммить** от своего имени.

Команды ниже проверены в песочнице на GitLab 17.5 CE. `T` — личный токен (Profile → Access tokens, scope `api`), `G` — адрес GitLab, `ID` — id проекта.

## Шаги
1. Войти как root, сменить пароль, включить 2FA (Profile → Account → Two-factor).
2. Admin → Users → New user ×5 (личные аккаунты). Роли по `docs/roles.md` (решите, кто Maintainer).
3. Создать проект `onec-config` (Public). Admin → Overview: запиши **редакцию** GitLab в `docs/regulation.md`.
4. Защита веток и тегов:
```
curl -H "PRIVATE-TOKEN: $T" -X POST "$G/api/v4/projects/$ID/protected_branches" -d name=main -d push_access_level=0 -d merge_access_level=40 -d allow_force_push=false
curl -H "PRIVATE-TOKEN: $T" -X POST "$G/api/v4/projects/$ID/protected_branches" -d 'name=release/*' -d push_access_level=0 -d merge_access_level=40 -d allow_force_push=false
curl -H "PRIVATE-TOKEN: $T" -X POST "$G/api/v4/projects/$ID/protected_tags" -d 'name=v*' -d create_access_level=40
```
   Первый push в `main` сделай до шага 4 (иначе push закрыт и для тебя).
5. Настройки MR:
```
curl -H "PRIVATE-TOKEN: $T" -X PUT "$G/api/v4/projects/$ID" -d only_allow_merge_if_pipeline_succeeds=true -d allow_merge_on_skipped_pipeline=false -d only_allow_merge_if_all_discussions_are_resolved=true -d squash_option=default_on -d remove_source_branch_after_merge=true
```
6. CI variables: `SONAR_HOST_URL=http://sonarqube:9000`, `SONAR_TOKEN` (masked; токен из Sonar → My Account → Security).
7. Runner: Admin → CI/CD → Runners → New instance runner, тег `docker`, «Run untagged» выключить → токен `glrt-…` отдай Есену для `register-runner-docker.sh`.
8. В корень `onec-config` положи `ci/.gitlab-ci.yml` как `.gitlab-ci.yml` и `ci/sonar-project.properties`.
