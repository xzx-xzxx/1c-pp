# ПАМЯТКА — Настя (1С №1)

> **Быстрый путь:** `bash pr.sh <PR> <issue> <путь к клону>` делает шаги 1, 2 и коммит за тебя (push — после доказательств).
> Сначала `РУКАМИ.md` (что делать руками), затем PR по этой памятке.

## Один раз настроить git
`git clone https://github.com/xzx-xzxx/1c-pp.git && cd 1c-pp`, затем `git config user.name "<имя>"` и `git config user.email "<почта GitHub>"`. Коммиты только из своего аккаунта.

## Твои PR (по одному на issue; Вероника заводит issues, номер подставь в `Closes #N`)
### N1-A — Демо-конфигурация в формате EDT (ревьюер: Надя)
1. `git switch main && git pull && git switch -c onec/demo-config-edt`
2. Скопируй содержимое `N1-A/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности. См. `N1-A/ЗАМЕТКА.md`.
3. Сделай то, что описано в `N1-A/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: edt-project-open.png (проект открыт в EDT) — ОБЯЗАТЕЛЬНО.
4. `git add -A && git commit -m "#N: демо-конфигурация в формате edt" && git push -u origin onec/demo-config-edt`
5. На GitHub: Compare & pull request, вставь `N1-A/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

### N1-B — Руководство разработчика (проверено руками) (ревьюер: Вероника)
1. `git switch main && git pull && git switch -c onec/dev-guide`
2. Скопируй содержимое `N1-B/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности.
3. Сделай то, что описано в `N1-B/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: dev-guide-walkthrough.txt (заметки или лог прохождения).
4. `git add -A && git commit -m "#N: руководство разработчика (проверено руками)" && git push -u origin onec/dev-guide`
5. На GitHub: Compare & pull request, вставь `N1-B/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

### N1-C — Конкурентный анализ (ревьюер: Надя)

2. Скопируй содержимое `N1-C/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности.
3. Сделай то, что описано в `N1-C/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: —.
4. `git add -A && git commit -m "#N: конкурентный анализ" && git push -u origin docs/competitors`
5. На GitHub: Compare & pull request, вставь `N1-C/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

## Твои ревью (чужие PR)
- `review/V-A.md` — PR V-A (Вероника, ветка `gitlab/roles-and-protection`)
- `review/V-C.md` — PR V-C (Вероника, ветка `docs/requirements-ai`)
- `review/N2-B.md` — PR N2-B (Надя, ветка `onec/prod-scenario`)
Как делать: открой PR → вкладка Files changed → выполни проверки из файла → поправь готовый комментарий под то, что реально увидел(а) → Approve или Request changes. Выдумывать замечания и результаты нельзя.
