# ПАМЯТКА — Есен (инфраструктура и GitHub)

> Сначала `РУКАМИ.md` (что делать руками), затем PR по этой памятке.

## Один раз настроить git
`git clone <ссылка на репо, которую даст Вероника> && cd <папка>`, затем `git config user.name "<имя>"` и `git config user.email "<почта GitHub>"`. Коммиты только из своего аккаунта.

## Твои PR (по одному на issue; Вероника заводит issues, номер подставь в `Closes #N`)
### E-A — Стенд в Docker Compose + quick start (ревьюер: Вероника)
1. `git switch main && git pull && git switch -c infra/compose-stand`
2. Скопируй содержимое `E-A/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности.
3. Сделай то, что описано в `E-A/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: stand-compose-ps.png (вывод docker compose ps) — если стенд поднимался.
4. `git add -A && git commit -m "#N: стенд в docker compose + quick start" && git push -u origin infra/compose-stand`
5. На GitHub: Compare & pull request, вставь `E-A/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

## Твои ревью (чужие PR)
Как делать: открой PR → вкладка Files changed → выполни проверки из файла → поправь готовый комментарий под то, что реально увидел(а) → Approve или Request changes. Выдумывать замечания и результаты нельзя.
