# ТЗ на перенос действующей среды разработки заказчика

## Цель
Перенести разработку конфигураций заказчика из текущего хранилища/процесса в Git + GitLab CI без потери истории и с сохранением работы команд.

## Этапы
1. Обследование: конфигурации, расширения, хранилища 1С, число разработчиков, текущий релизный процесс.
2. Развёртывание стенда (GitLab, Sonar, runner'ы, платформа).
3. Миграция истории из хранилища в Git (инструменты вроде gitsync; точность выбирается пилотом).
4. Пилот на одной конфигурации, 1–2 релизных цикла.
5. Обучение разработчиков (`dev-guide.md`, `regulation.md`).
6. Масштабирование на остальные конфигурации, отключение старого процесса.

## Требования
Формат EDT; роли по `roles.md`; pipeline по `pipeline.md`; бэкапы по расписанию; лицензии платформы у заказчика; доступ по HTTPS и 2FA.

## Риски
| Риск | Мера |
| --- | --- |
| Потеря истории при миграции | пилот + сверка выборки версий |
| Сопротивление команд | обучение, параллельная работа на пилоте |
| Лицензии/ресурсы сервера | оценка до старта, отдельный раннер |
| Ложные срабатывания BSL | настройка правил, постепенное включение блокировок |

## Критерии приёмки
Вся история пилотной конфигурации в Git; pipeline на MR работает; релиз собран и обновил тестовый контур; прод-сценарий прогнан на копии; документы переданы.
