# ПАМЯТКА — Надя (1С №2)

> Сначала `РУКАМИ.md` (что делать руками), затем PR по этой памятке.

## Один раз настроить git
`git clone <ссылка на репо, которую даст Вероника> && cd <папка>`, затем `git config user.name "<имя>"` и `git config user.email "<почта GitHub>"`. Коммиты только из своего аккаунта.

## Твои PR (по одному на issue; Вероника заводит issues, номер подставь в `Closes #N`)
### N2-A — Платформа 1С и раннер onec (ревьюер: Соня)
1. `git switch main && git pull && git switch -c onec/platform-runner`
2. Скопируй содержимое `N2-A/files/` в корень клона (пути уже совпадают с репозиторием). Прочитай файлы, поправь по реальности.
3. Сделай то, что описано в `N2-A/pr-description.md` («Как проверить»), и положи доказательства в `docs/evidence/`: platform-version.txt (реальный вывод версии платформы).
4. `git add -A && git commit -m "#N: платформа 1с и раннер onec" && git push -u origin onec/platform-runner`
5. На GitHub: Compare & pull request, вставь `N2-A/pr-description.md`, заполни поля `[впиши]`. Не запускал(а) — так и пиши. После approve — squash-merge сам(а).

## Твои ревью (чужие PR)
- `review/N1-A.md` — PR N1-A (Настя, ветка `onec/demo-config-edt`)
- `review/N1-C.md` — PR N1-C (Настя, ветка `docs/competitors`)
- `review/S-B.md` — PR S-B (Соня, ветка `qa/demo-branches-scenario`)
Как делать: открой PR → вкладка Files changed → выполни проверки из файла → поправь готовый комментарий под то, что реально увидел(а) → Approve или Request changes. Выдумывать замечания и результаты нельзя.
