# Обновление продуктива

> Скрипты `deploy-prod.sh`, `rollback.sh` написаны, **на тестовой копии не прогонялись** до подтверждения людьми.

## Шаги
1. Релиз протестирован на тестовом контуре, есть тег `vX.Y.Z` и артефакт.
2. Ответственный за релиз (Maintainer) запускает manual job `deploy-prod` с `CONFIRM=yes` — это подтверждение.
3. Скрипт делает выгрузку ИБ `.dt` и проверяет, что файл не пуст.
4. Загрузка `.cf`, обновление конфигурации БД.
5. Проверка работоспособности (смоук-тест — не реализован, ручная проверка по чек-листу).
6. При сбое скрипт сам вызывает `rollback.sh`; вручную: `PROD_IB=… BACKUP_DIR=… ci/scripts/rollback.sh [файл.dt]`.

## Чек-лист
- [ ] Есть свежий бэкап и он восстанавливается на копии
- [ ] Согласовано окно обновления, пользователи предупреждены
- [ ] Тег и артефакт совпадают с тем, что проверено на тесте
- [ ] После обновления выполнена ручная проверка
- [ ] Бэкап сохранён до следующего релиза
